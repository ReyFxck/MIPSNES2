# Cartridge destination and machine-region audit

Date: 2026-11-02

## Scope

This block makes the selected cartridge header's destination byte available as
an explicit `UNKNOWN`, `NTSC` or `PAL` classification and lets a machine caller
opt into that result. The PS2 ROM path opts in with NTSC as its fallback. This
changes H/V frame length, PPU region status and the existing regional APU clock
ratio together; it does not add a launcher loop or a game-specific exception.

The implementation remains allocation-free and platform-neutral. Cartridge
analysis owns destination interpretation, the machine owns the selected timing
standard, and PS2SDK remains outside `core/`.

## Evidence and conservative policy

Nintendo's *SNES Development Manual, Book I*, ROM Registration Data
Specification pages 1-2-14 through 1-2-20, defines `$FFD9` as the Destination
Code and lists the intended markets. PPU register page 2-27-23 independently
defines `$213F` bit 4 as the hardware NTSC/PAL display-method status. The manual
does not define a universal conversion for every destination value, so MIPSNES2
keeps unassigned codes, Chinese, Common and Other Variation destinations
unknown. No emulator source or game database was consulted.

The implemented timing groups are:

- NTSC: Japan, North America, South Korea, Canada, and the shared
  Brazil/Nintendo Gateway code;
- PAL: Europe, Scandinavia, French Europe, Dutch, Spanish, German, Italian and
  Australia;
- unknown: codes absent from Nintendo's table, Chinese, Common, Other Variation
  and all other values.

Brazil's PAL-M television encoding and the Gateway code share a 60 Hz-oriented
destination byte; this classification selects the existing 262-line SNES timing
model, not an analog video encoder. Ambiguous codes use the caller's explicit
fallback rather than a guessed standard.

## Deterministic verification

- direct classification covers every documented group plus ambiguous and
  unassigned values;
- parsed LoROM headers retain the derived region;
- cartridge plans propagate the selected candidate's region;
- machine tests prove opt-out behavior, NTSC and PAL override, unknown fallback,
  H/V state selection and clean reinitialization after changing a synthetic
  header and recalculating its checksum;
- the PS2 explicit-ROM configuration opts in while retaining NTSC fallback.

All fixtures are original generated byte arrays. Cross-build success cannot
establish that a commercial ROM boots or that physical PS2 presentation is
correct.
