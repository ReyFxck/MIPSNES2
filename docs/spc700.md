# SPC700

## Scope and current state

Own SPC700 registers, flags, instruction execution, local RAM/I/O and timers. SPC700 is independent of the 65C816 and target CPU. IPL data origin/licensing must be resolved before committing any boot image. Caller-owned register state and a bounded atomic execution foundation exist for `NOP` and eight PSW-control instructions; this is not a complete interpreter. A separate shared communication-port mailbox provides the logical S-CPU/S-SMP boundary. Successful instruction costs advance the three timers, but no clock domain synchronizes execution with the S-CPU or S-DSP.

## Design direction

Document memory and port semantics, timer divisors and instruction costs from primary research. Scheduler advances APU time deterministically; do not substitute host timing or make the IOP responsible for SNES timing by default.

## Verification criteria

Test every opcode/addressing class, flags, stack, multiplication/division, decimal adjust, bit operations and sleep/stop interactions. Verify communication races, timer wrap/reset and long-run clock ratios with targeted integration fixtures.

## Research and decisions

Intentional approximation: internal communication latches reset to zero and
opposite-side API visibility is immediate until the S-SMP clock domain exists. Timer
targets, outputs and shared prescaler phase also start at deterministic zero; real
power-on values and the DSP-relative phase are not claimed. Timer advancement is
caller-driven in S-SMP cycles until an interpreter/scheduler owns that time.
Unsupported opcodes fail explicitly after fetch and before architectural/time
commit; memory-mapped fetches can retain their documented read side effects. Exact
bus-cycle phases, reset sequencing and interrupts are not modeled. See the
[communication-port audit](apu-io-port-audit.md),
[memory-map audit](smp-memory-map-audit.md) and
[timer audit](smp-timer-audit.md), plus the
[execution audit](spc700-execution-foundation-audit.md).
