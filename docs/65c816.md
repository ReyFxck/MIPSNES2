# 65C816

## Scope and current state

The reference C interpreter owns caller-allocated A, X, Y, S, D, DBR, PBR, PC, P
and E state, a logical bus connection, IRQ/NMI/ABORT inputs, WAI/STP state, diagnostic
stop state and completed-instruction cycle accounting. It is platform independent
and stores no PS2/PSP physical address. All 256 opcode values dispatch. A partial
SNES bus/timing bridge now charges meaningful accesses by Ricoh 5A22 address speed
and advances the central scheduler. The opt-in resumable bridge consumes the
caller-owned peek/commit cursor for all 256 opcode values, boundary interrupts
and RESET vector reads. A bounded mid-instruction ABORT pulse restores pre-fetch
registers and enters the ABORT cursor at the following boundary; per-byte writes
block until the caller explicitly chooses external effect or target inhibition.
Full ABORT electrical behavior and RTI/interrupt exceptions,
signal-level RESET/bus cycles and complete dummy/internal sequences remain open.

## State and width invariants

`A`, `X`, `Y`, `S`, `D` and `PC` use 16-bit storage. `DBR`, `PBR` and `P` use 8-bit
storage; E is separate because it is not an ordinary P bit. A fetch uses `PBR:PC`
and increments only the 16-bit PC, so it wraps within the current program bank.
Absolute operands begin at `DBR:operand`. Data accesses are linear 24-bit accesses:
a 16-bit operand at `xx:FFFF` takes its high byte from `(xx+1):0000`, and the full
address space wraps from `FF:FFFF` to `00:0000`. Absolute indexed addressing adds X
or Y to the full `DBR:operand` address, so indexing may carry into the next bank.
Absolute long operands contain all 24 address bits and ignore DBR; long indexed adds
X to that full address. Instruction fetch still wraps the 16-bit PC within PBR.

Implemented Direct and Direct-indexed operands ignore DBR and always address bank
zero. Normally, effective address is the low 16 bits of `D + operand + index`. The
WDC emulation-mode exception applies when E=1 and DL=0: the sum wraps its low byte
within the page selected by DH instead of carrying into the next page. When DL is
nonzero, the addition uses the full 16-bit bank-zero range even in emulation mode.
Native-mode 16-bit Direct data wraps from `00:FFFF` to `00:0000`; it never crosses
into bank 01.

Implemented regular Direct-indirect forms read a 16-bit pointer from bank zero. In
E=1 with DL=0, both pointer bytes follow the aligned Direct Page wrap rule; otherwise
they advance through the full 16-bit bank-zero range. `(direct,X)` adds X before the
pointer read. DBR supplies the data bank for `(direct,X)`, `(direct)` and `(direct),Y`.
The post-indexed form adds Y to the resulting full 24-bit address, so it may carry
into the next bank.

Implemented Direct-indirect-long forms read all three pointer bytes from bank zero
and ignore DBR for the final data address. WDC caveat 7.2 exempts these pointer reads
from the aligned-emulation page wrap: the second and third bytes advance linearly,
including from `00:xxFF` into `00:(xx+1)00`; the bank-zero address itself wraps at
`00:FFFF`. `[direct],Y` adds Y to the full 24-bit pointer and may carry across a bank.

Implemented stack-relative operands add the unsigned 8-bit instruction offset to the
full 16-bit S register, wrap that sum modulo 16 bits and always access bank zero.
This is independent of D and does not use the emulation-mode Direct Page low-byte
wrap rule. A 16-bit load or store at `00:FFFF` accesses its high byte at `00:0000`.
Stack-relative-indirect-indexed forms read a little-endian 16-bit pointer from that
bank-zero address with the same bank-zero wrap, combine it with DBR, then add the
architectural Y value across the full 24-bit address space. No stack pointer, DBR,
Y or mode state is modified.

Stack pushes and pulls always emit logical bank-zero addresses. Ordinary single-byte
operations write at S and then decrement, or increment S and then read. PHA/PLA use
M-selected width; PHX/PLX and PHY/PLY use X-selected width. A 16-bit push writes the
high byte first and the low byte second, while a 16-bit pull reads low then high.
PHP and PLP always transfer one byte. PLA, PLX, PLY, PLB and PLD set N/Z from the
pulled value at their architectural width; PLP replaces P and then reapplies E/M/X
invariants. Other pushes preserve status.

When E=1, ordinary byte-at-a-time stack adjustment wraps within `01xx`. WDC caveat
7.1 separately identifies `JSL`, `JSR (a,X)`, `PEA`, `PEI`, `PER`, `PHD`, `PLD` and
`RTL` as multi-byte operations that may access outside `01xx`. Those instructions
therefore form consecutive 16-bit bank-zero addresses from the starting S and only
then restore the architectural `SH=01` invariant. This is intentionally not folded
into the ordinary push/pull helper.

Absolute JMP and JSR retain PBR. Absolute-long JMP and JSL replace PBR from their
operand. `JMP (absolute)` reads a 16-bit target pointer from bank zero; `JMP
(absolute,X)` and `JSR (absolute,X)` read their pointer table in PBR. `JMP
[absolute]` reads a 24-bit pointer from bank zero and replaces both PC and PBR. JSR
pushes the address of its final operand byte high then low. JSL pushes the old PBR,
then that return address high and low. RTS/RTL pull the saved address and add one;
RTL also pulls PBR. PER adds a signed 16-bit operand to the already-advanced PC and
pushes the resulting 16-bit address without changing PBR. PEA pushes its immediate
word, while PEI reads a Direct Page 16-bit pointer using the established E/DL wrap
rule and pushes that word.

When M is one, an 8-bit LDA changes only the low accumulator byte and preserves B.
When X is one, X/Y are 8-bit and their high bytes are zero. E=1 forces M=X=1,
`SH=01`, and zero XH/YH. REP cannot clear M/X in emulation mode. XCE exchanges C
and E, then applies these invariants. N/Z use the selected destination width.

Implemented A/X/Y register transfers expose the architectural 16-bit source value;
when X=1 the forced-zero index high byte therefore participates as zero. TAX/TAY use
X to select destination width even when M=1, so a 16-bit destination receives both A
and B. TXA/TYA use M to select destination width: an 8-bit destination preserves B,
while a 16-bit destination receives the full (possibly zero-extended) index. TXY/TYX
use X for both registers. In all six operations, N/Z reflect the destination width
and the other status bits are unchanged.

TCD, TCS, TDC and TSC always transfer the full 16-bit C, D or S value regardless of
M. TCD, TDC and TSC set N/Z from that 16-bit result; TCS leaves status unchanged.
TCS and TXS force the stack high byte to `01` only in emulation mode. In native mode,
TCS stores the full accumulator and TXS stores the architectural X value. TSX uses X
to select its destination width, including high-byte clearing for an 8-bit X. TXS
does not change flags. XBA exchanges A and B independently of M/E, then sets N/Z from
the new low accumulator byte while preserving the other status bits.

All eight conditional branches test N, V, C or Z without modifying P. Relative
offsets are signed and are added to the PC after the complete instruction has been
fetched. BRA uses the same signed 8-bit target rule unconditionally; BRL uses a
signed 16-bit offset. Both PC arithmetic paths wrap modulo 16 bits and leave PBR
unchanged, including when the operand fetch or target crosses `FFFF/0000`. Explicit
arithmetic sign extension avoids relying on implementation-defined unsigned-to-
signed casts in host or console toolchains.

CLD/SED change only D, CLI/SEI change only I, and CLV changes only V. Each is a
one-byte implied instruction with identical behavior in emulation and native modes;
no register, E bit, width bit or unrelated status flag changes.

Accumulator INC/DEC wrap at the M-selected 8/16-bit width. In 8-bit mode they update
only A and preserve B. INX/DEX/INY/DEY wrap at the X-selected width; an 8-bit index
result remains zero-extended. All six update only N/Z from their selected-width
result, preserve every other status bit and do not change E or unrelated registers.

ORA, AND and EOR use M-selected width, write the result to the accumulator and update
only N/Z. Their 8-bit forms preserve B. CMP uses M-selected accumulator width; CPX
and CPY use X-selected index width. Comparisons do not store the subtraction result:
they set N/Z from that selected-width result and set C when the register is greater
than or equal to the operand (no borrow), preserving every other status bit.

The listed ADC and SBC forms use M-selected width, preserve B in 8-bit mode and
update C/V/N/Z while preserving all other status bits. With D=0, ADC computes
`A + operand + C`; SBC treats C as no-borrow and computes
`A - operand - (1 - C)`. With D=1, packed-BCD correction is applied independently
across two or four nibbles for 8- or 16-bit operation. C reports decimal carry or
no-borrow, N/Z reflect the corrected result, and V reflects the binary overflow
stage: ADC uses the pre-correction highest-nibble sum and SBC uses the binary
subtraction result. Inputs containing hexadecimal A-F nibbles remain deterministic
and are covered by independent vectors; they are not rejected or normalized.

Direct and Direct-X operands use bank zero and the existing Direct Page wrapping
rules; absolute and absolute-X/Y operands use DBR and linear 24-bit data-word access.
Stack-relative operands use the full 16-bit `S + offset` in bank zero.
Stack-relative-indirect-indexed pointers wrap in bank zero, then select DBR and add
Y with 24-bit carry. Regular Direct-indirect forms use a bank-zero wrapping pointer
and DBR; `(direct,X)` pre-indexes the pointer address and `(direct),Y` post-indexes
the resulting data address.

BIT never changes the accumulator. It selects operand width with M and sets Z from
the selected-width `A AND operand`. Direct, Direct-X, absolute and absolute-X BIT
copy the operand's selected-width top bit to N and next bit to V. Immediate BIT
changes only Z and preserves N/V. CPX, CPY, BIT, ORA, AND, EOR and CMP now have every
architectural opcode represented.

ASL, LSR, ROL and ROR operate at the M-selected width. Accumulator forms preserve B
when M=1; memory forms update the selected one- or two-byte operand. ASL and LSR
shift zero into the vacated bit, while ROL and ROR shift the incoming C value into
the result. All four set C from the bit shifted out and update N/Z from the result,
preserving unrelated flags. Memory INC/DEC wrap at the M-selected width and update
only N/Z. TSB and TRB set Z from `A AND original memory`, then respectively set or
clear the accumulator-selected bits in memory; they change no other flag. STZ writes
an M-selected zero and preserves all flags and registers. Direct/Direct-X forms use
bank zero and the existing Direct Page rules. Absolute/absolute-X forms use DBR and
the same linear 24-bit word and full-address indexed carry rules as other data
accesses.

The object is caller-owned and uses no heap allocation. `mipsnes2_cpu_init` creates
a deterministic, stopped object; it is not a hardware power-on claim. RESET must
succeed before stepping.

## Interrupt, wait and block-move contract

`BRK` and `COP` consume their signature byte before stacking the return PC. Native
mode pushes PBR, PCH, PCL and P; emulation mode omits PBR and uses ordinary `01xx`
stack wrapping. Both clear D, set I and set PBR to zero after saving P. `BRK` uses
`00:FFFE` in emulation and `00:FFE6` in native mode; `COP` uses `00:FFF4` and
`00:FFE4`. `RTI` pulls P, PCL and PCH, then also PBR in native mode, and reapplies
the E/M/X invariants after restoring status.

The caller drives the level-sensitive IRQ input with `mipsnes2_cpu_set_irq`, latches
an NMI edge with `mipsnes2_cpu_pulse_nmi`, and latches a boundary-visible ABORT pulse
with `mipsnes2_cpu_pulse_abort`. At an instruction boundary the implemented priority
is ABORT, NMI, then IRQ. An unmasked IRQ or NMI uses the appropriate
emulation/native vector, stacks the current return address, clears D and sets I.
Emulation-mode BRK stacks bit 4 set; COP and hardware interrupts stack it clear. IRQ remains
ignored while I is set, except that an asserted IRQ releases `WAI` and execution
continues with the following instruction. NMI also releases `WAI` and enters its
handler. `STP` returns `MIPSNES2_CPU_CLOCK_STOPPED` on later steps and only RESET
clears that state; an idle WAI returns `MIPSNES2_CPU_WAITING` without bus access or
cycle advancement.

The current ABORT foundation is deliberately narrower than the physical signal.
When pulsed before `mipsnes2_cpu_step`, ABORT enters before an opcode fetch, stacks
the current PBR:PC as the aborted-opcode return address, uses `00:FFF8-FFF9` in
emulation or `00:FFE8-FFE9` in native mode, clears D, sets I and takes the shared
seven/eight-cycle hardware-interrupt aggregate. Native mode pushes PBR; emulation
does not and stacks bit 4 clear. A pulse while WAI is already waiting does not wake
the CPU; it restores PBR:PC to the WAI opcode so a later accepted interrupt stacks
that restart address. RESET clears the pending latch and STP ignores it until RESET.

This API does not pretend to sample ABORT during an atomic instruction. The physical
input can suppress current-instruction register changes and has cycle-sensitive
exceptions for read-modify-write, RTI and interrupt entry. Correctly reproducing
those cases requires the same resumable cycle/micro-operation contract already
required for mid-instruction scheduler dispatch. The broad ABORT task therefore
remains in progress.

The optional machine-wiring layer `mipsnes2_interrupt_lines` aggregates independent
internal-timer, cartridge and expansion IRQ levels before driving this single CPU
input. Its CPU-I/O sampler transfers the latched NMI edge without coupling the CPU
core to Ricoh registers. The H/V-aware interrupt timing bridge samples before and
after one atomic CPU step: pre-existing inputs participate in that boundary, while
inputs generated during the step remain pending for the next. Exact internal-cycle
sampling is not represented yet.

`MVP` and `MVN` fetch destination bank followed by source bank, copy one byte from
`source:X` to `destination:Y`, set DBR to the destination bank, update X/Y in the
selected index width and decrement the full 16-bit A counter. One byte is processed
per `mipsnes2_cpu_step`: PC rewinds to the opcode while A has not wrapped to `FFFF`,
then remains after the three-byte instruction on completion. This resumable contract
preserves an instruction boundary for the future central scheduler. `WDM` consumes
its signature byte and otherwise preserves processor state.

## RESET foundation

RESET currently applies only sourced programmer-visible invariants and reads the
little-endian vector from logical `00:FFFC-D`:

- E=1, M=1, X=1 and I=1; D is cleared;
- D, DBR and PBR become zero;
- XH and YH become zero; SH becomes `01`;
- PC is loaded from `00FFFC-D`;
- A, XL, YL, SL and N/V/Z/C are not claimed to have defined hardware reset values.

For deterministic state, fields the hardware reference labels uninitialized retain
their initialized low bits/current flags. This is an emulator storage policy, not a
claim about physical power-on contents. RESET clears WAI, STP and latched ABORT/NMI;
the externally driven IRQ level remains owned by the caller. RESET bus cycles,
signal-level sequencing and timing are not implemented, so the broad RESET task
remains in progress.

## Timing contract

`instruction_cycles` counts W65C816S base processor cycles for successfully completed
instructions. Immediate, absolute and absolute-long 16-bit data adds the documented
width cycle. Absolute indexed reads add one cycle when indexing crosses a page or X
is 16-bit; indexed stores always take that indexed cycle. These conditions share one
cycle rather than stacking. Direct forms use three base cycles and Direct-indexed
forms use four; one cycle is added when DL is nonzero, and a 16-bit data transfer
adds its documented width cycle. The implemented Direct-indirect base cycles are
five or six as listed by the WDC opcode table. They add the same DL and M-width
cycles. `(direct),Y` LDA adds one shared indexed-read cycle when Y crosses a page or
X selects 16-bit index width, while its store has the fixed six-cycle base. The DL,
data-width and applicable indexed-read additions stack. Conditional relative branches
take two cycles when not taken and three when taken. A taken relative branch adds one
more cycle when it crosses a page in emulation mode only; BRA is always taken and
follows the same rule. BRL always takes four cycles and has no page penalty. TAX,
TAY, TCD, TCS, TDC, TSC, TSX, TXA, TXS, TYA, TXY and TYX each take two cycles at
either width. CLC, CLD, CLI, CLV, SEC, SED and SEI also take two cycles. XBA takes
three cycles. Accumulator INC/DEC and INX/DEX/INY/DEY take two cycles at either
selected width. WDM takes two cycles; WAI and STP take three. BRK/COP and hardware
IRQ/NMI/ABORT entry take seven cycles in emulation and eight in native mode. RTI
takes six cycles in emulation and seven in native mode. Each MVP/MVN byte takes seven cycles.
RESET and a defensive unimplemented-opcode result add no cycles. The
counter is not itself SNES master time. `mipsnes2_cpu_timed_step` combines it with
observed SNES-bus accesses: each meaningful callback uses its address-speed class,
and the remaining aggregate cycles are provisionally charged as 6-clock internal
cycles. Wait states, refresh, bus arbitration and DMA remain outside that partial
central timing model.

The public `mipsnes2_cpu_step` remains atomic at the instruction boundary. Under it,
a caller-owned peek/commit cursor now exposes operation boundaries for all 256
opcode values when read and write bus callbacks are present. The final 101
`ORA/AND/EOR/ADC/SBC/CMP/CPX/CPY/BIT` forms reuse the load/store operand, address,
pointer and width phases, while `RTI`, `WDM`, `MVP`, `MVN`, `WAI` and `STP` use
dedicated control phases. Boundary `ABORT`, `NMI` and `IRQ` entry also use the
cursor. Repeated peek is side-effect free, commit performs one described operation,
and a changed descriptor is rejected before an effect. Width-selected operands, PC
wrap, low-before-high stores, status invariants, subroutine stack order, interrupt
stack/vector order and accumulated processor cycles have deterministic host coverage.

`LEGACY_ATOMIC` remains only for missing-write fail-stop preflight. RESET uses a
zero-time control descriptor and explicit `00:FFFC-D` reads, while the public reset
wrapper drives them atomically and retains the established zero-cycle accounting.
Dummy cycles and signal-level activity are still atomic or absent. Active cursor state
must be retained without interleaving another CPU step. The scheduler therefore
continues to use the instruction-atomic bridge and must not run events from bus
callbacks. A
rejected synchronous clock-sink experiment could partially commit an instruction
when event dispatch failed; see the [access-timing post-mortem](cpu-access-timing-postmortem.md),
[initial cursor audit](65c816-cycle-contract-audit.md) and
[interrupt-cycle audit](65c816-interrupt-cycle-audit.md), followed by the
[subroutine-cycle audit](65c816-subroutine-cycle-audit.md) and the
[long-subroutine-cycle audit](65c816-long-subroutine-cycle-audit.md), then the
[indexed-subroutine-cycle audit](65c816-indexed-subroutine-cycle-audit.md) and the
[jump-cycle audit](65c816-jump-cycle-audit.md), then the
[resumable branch-cycle audit](65c816-resumable-branch-cycle-audit.md) and the
[stack-cycle audit](65c816-stack-cycle-audit.md), followed by the
[implied-cycle audit](65c816-implied-cycle-audit.md) and the
[load/store-cycle audit](65c816-load-store-cycle-audit.md), plus the
[read/modify/write-cycle audit](65c816-rmw-cycle-audit.md), and finally the
[complete opcode-cycle audit](65c816-final-resumable-cycle-audit.md) and

PHP, PHB, PHK and 8-bit PHA/PHX/PHY take three cycles; their width-selected 16-bit
forms take four. PLP and PLB take four cycles. Eight-bit PLA/PLX/PLY take four cycles
and their 16-bit forms take five. PHD takes four and PLD takes five. PEA takes five;
PEI and PER take six, with PEI adding one cycle when DL is nonzero. JSR absolute and
RTS take six cycles, JSL and JSR `(absolute,X)` take eight, RTL takes six, JMP
absolute-long takes four, JMP `(absolute)` takes five, and JMP `(absolute,X)` plus
JMP `[absolute]` take six. These are aggregate completed-instruction totals; internal
dummy reads are not exposed by the current callback interface. Tests do verify the
meaningful operand, pointer and stack callback order for JSL and JSR `(absolute,X)`.
The resumable jump regressions additionally verify every `JMP/JML` operand and
pointer operation, including the indexed form's internal-cycle position.
The resumable branch regressions verify all eight flag conditions in both outcomes,
BRA, BRL, signed extrema, bank-local wrapping and the emulation-only taken
page-cross cycle.

The implemented ORA/AND/EOR/CMP, CPX/CPY and BIT forms use their WDC base cycles:
two for 8-bit immediate, three for aligned 8-bit Direct and four for 8-bit absolute.
Selected 16-bit data adds one cycle. Direct modes add one when DL is nonzero. ORA/AND/EOR/CMP
Direct-X starts at four cycles; `(direct)`, `(direct),Y` and `(direct,X)` start at
five, five and six cycles respectively; `[direct]` and `[direct],Y` start at six.
Absolute indexed starts at four cycles and absolute-long/absolute-long-X at five.
The applicable indexed-read cycle is shared when X is 16-bit or a page is crossed;
DL, M-width and that indexed condition stack. BIT Direct-X starts at four cycles and
BIT absolute-X follows the same indexed-read rule.

Stack-relative accumulator loads, stores and ALU reads start at four cycles;
stack-relative-indirect-indexed forms start at seven. M=0 adds one data-width cycle. These modes do not add
Direct Page low-byte, page-cross or X-width cycles.
ADC/SBC take the same cycle count in binary and decimal modes. Immediate forms take
two cycles with M=1 and three with M=0. Direct forms
start at three cycles, Direct-X at four, and both add one when DL is nonzero;
absolute and absolute-X/Y forms start at four. Absolute indexed reads add the shared
indexed cycle when X selects 16-bit indexes or indexing crosses a page. Every memory
form adds one more cycle when M=0.
Stack-relative ADC/SBC start at four cycles and stack-relative-indirect-indexed forms
at seven; M=0 adds one cycle. They do not add Direct Page, page-cross or X-width
penalties.
Regular Direct-indirect ADC/SBC start at five cycles, while `(direct,X)` starts at
six. `(direct),Y` adds one shared indexed-read cycle when X selects 16-bit indexes or
Y crosses a page. DL and M-width additions stack with the applicable indexed cycle.
Direct-indirect-long ADC/SBC forms start at six cycles and add the DL and M-width
cycles. Absolute-long and absolute-long-X ADC/SBC start at five cycles and add only
the M-width cycle. The long indexed forms do not add page-cross or X-width cycles.

Accumulator ASL/LSR/ROL/ROR take two cycles at either M width. Their memory forms
use 8-bit base totals of five cycles for Direct, six for Direct-X, six for absolute
and seven for absolute-X. M=0 adds two cycles for the wider read-modify-write, and
Direct/Direct-X add the existing DL penalty. Indexed memory RMW timing is fixed and
does not gain a separate page-cross or X-width penalty. Memory INC/DEC use the same
rules. TSB/TRB use five cycles for Direct and six for absolute in M=1, with two more
cycles in M=0 and the Direct DL penalty. STZ uses three, four, four and five cycles
for Direct, Direct-X, absolute and absolute-X respectively in M=1, adds one when
M=0, and adds the Direct DL penalty where applicable. This is aggregate instruction
timing only: the reference bus does not yet expose the W65C816 dummy/modify write
sequence or MLB lock signaling.

## Remaining work

All 256 opcode values now have explicit reference-C behavior. The deterministic
scheduler and partial SNES bus now convert meaningful accesses into address-dependent
5A22 clocks, but the interpreter still reports aggregate W65C816 totals rather than
every bus/internal cycle. Remaining CPU work is outside opcode enumeration:
mid-instruction ABORT rollback/restart and signal sampling, signal-level RESET
sequencing, dummy/internal cycle addresses and placement, MLB signaling,
mid-instruction event boundaries, scheduler arbitration
and broader independent CPU-vector/test-ROM validation. IRQ
and NMI entry exist at the CPU boundary; SNES register generation, enable/compare
logic and event timing remain Phase 4 work. Do not infer complete SNES CPU-subsystem
integration or dynarec justification from the completed opcode dispatch.

The detailed state is canonical in [STATUS.md](../STATUS.md).
