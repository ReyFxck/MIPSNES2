# 65C816

## Scope and current state

CPU owns A, X, Y, S, D, DBR, PBR, PC, P and the E/native-mode state. M and X width rules, emulation-mode stack rules and high-byte behavior need explicit invariants. Never store PS2/PSP physical addresses in CPU state. Implement a reference interpreter before investigating dynarec.

## Design direction

Start with reset state and vector reads through a minimal logical bus fixture. Specify instruction effects, addressing wrap and cycle additions using hardware evidence. Separate fetch/decode, effective-address calculation and execution only where it does not impose unmeasured hot-path overhead. Interrupts must coordinate with the scheduler rather than ad hoc game timing.

## Verification criteria

Test all width/mode combinations, carry/overflow/zero/negative, decimal edges, bank boundaries, Direct Page alignment and stack wrap. Include IRQ/NMI/RESET/BRK/COP, WAI wakeup and STP reset. Exhaustive small-domain arithmetic tests and opcode coverage must precede interpreter completion.

record the exact hardware reference, section/revision and independently authored
regression evidence. SDK documentation is not a source for SNES behavior.
