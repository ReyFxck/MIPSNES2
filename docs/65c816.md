# 65C816

## Scope and current state

The reference C interpreter subset owns caller-allocated A, X, Y, S, D, DBR, PBR,
PC, P and E state, a logical bus connection, diagnostic stop state and completed-
instruction cycle accounting. It is platform independent and stores no PS2/PSP
physical address. It is deliberately a partial interpreter, not a complete CPU.

## State and width invariants

`A`, `X`, `Y`, `S`, `D` and `PC` use 16-bit storage. `DBR`, `PBR` and `P` use 8-bit
storage; E is separate because it is not an ordinary P bit. A fetch uses `PBR:PC`
and increments only the 16-bit PC, so it wraps within the current program bank.
Absolute operands begin at `DBR:operand`. Data accesses are linear 24-bit accesses:
a 16-bit operand at `xx:FFFF` takes its high byte from `(xx+1):0000`, and the full
address space wraps from `FF:FFFF` to `00:0000`. Absolute indexed addressing adds X
or Y to the full `DBR:operand` address, so indexing may carry into the next bank.
Absolute long operands contain all 24 address bits and ignore DBR; long indexed adds
X to that full address. Instruction fetch still wraps the 16-bit PC within PBR.

Implemented Direct and Direct-indexed operands ignore DBR and always address bank
zero. Normally, effective address is the low 16 bits of `D + operand + index`. The
WDC emulation-mode exception applies when E=1 and DL=0: the sum wraps its low byte
within the page selected by DH instead of carrying into the next page. When DL is
nonzero, the addition uses the full 16-bit bank-zero range even in emulation mode.
Native-mode 16-bit Direct data wraps from `00:FFFF` to `00:0000`; it never crosses
into bank 01.

Implemented regular Direct-indirect forms read a 16-bit pointer from bank zero. In
E=1 with DL=0, both pointer bytes follow the aligned Direct Page wrap rule; otherwise
they advance through the full 16-bit bank-zero range. `(direct,X)` adds X before the
pointer read. DBR supplies the data bank for `(direct,X)`, `(direct)` and `(direct),Y`.
The post-indexed form adds Y to the resulting full 24-bit address, so it may carry
into the next bank.

Implemented Direct-indirect-long forms read all three pointer bytes from bank zero
and ignore DBR for the final data address. WDC caveat 7.2 exempts these pointer reads
from the aligned-emulation page wrap: the second and third bytes advance linearly,
including from `00:xxFF` into `00:(xx+1)00`; the bank-zero address itself wraps at
`00:FFFF`. `[direct],Y` adds Y to the full 24-bit pointer and may carry across a bank.

When M is one, an 8-bit LDA changes only the low accumulator byte and preserves B.
When X is one, X/Y are 8-bit and their high bytes are zero. E=1 forces M=X=1,
`SH=01`, and zero XH/YH. REP cannot clear M/X in emulation mode. XCE exchanges C
and E, then applies these invariants. N/Z use the selected destination width.

Implemented A/X/Y register transfers expose the architectural 16-bit source value;
when X=1 the forced-zero index high byte therefore participates as zero. TAX/TAY use
X to select destination width even when M=1, so a 16-bit destination receives both A
and B. TXA/TYA use M to select destination width: an 8-bit destination preserves B,
while a 16-bit destination receives the full (possibly zero-extended) index. TXY/TYX
use X for both registers. In all six operations, N/Z reflect the destination width
and the other status bits are unchanged.

TCD, TCS, TDC and TSC always transfer the full 16-bit C, D or S value regardless of
M. TCD, TDC and TSC set N/Z from that 16-bit result; TCS leaves status unchanged.
TCS and TXS force the stack high byte to `01` only in emulation mode. In native mode,
TCS stores the full accumulator and TXS stores the architectural X value. TSX uses X
to select its destination width, including high-byte clearing for an 8-bit X. TXS
does not change flags. XBA exchanges A and B independently of M/E, then sets N/Z from
the new low accumulator byte while preserving the other status bits.

All eight conditional branches test N, V, C or Z without modifying P. Relative
offsets are signed and are added to the PC after the complete instruction has been
fetched. BRA uses the same signed 8-bit target rule unconditionally; BRL uses a
signed 16-bit offset. Both PC arithmetic paths wrap modulo 16 bits and leave PBR
unchanged, including when the operand fetch or target crosses `FFFF/0000`. Explicit
arithmetic sign extension avoids relying on implementation-defined unsigned-to-
signed casts in host or console toolchains.

CLD/SED change only D, CLI/SEI change only I, and CLV changes only V. Each is a
one-byte implied instruction with identical behavior in emulation and native modes;
no register, E bit, width bit or unrelated status flag changes.

Accumulator INC/DEC wrap at the M-selected 8/16-bit width. In 8-bit mode they update
only A and preserve B. INX/DEX/INY/DEY wrap at the X-selected width; an 8-bit index
result remains zero-extended. All six update only N/Z from their selected-width
result, preserve every other status bit and do not change E or unrelated registers.

The object is caller-owned and uses no heap allocation. `mipsnes2_cpu_init` creates
a deterministic, stopped object; it is not a hardware power-on claim. RESET must
succeed before stepping.

## RESET foundation

RESET currently applies only sourced programmer-visible invariants and reads the
little-endian vector from logical `00:FFFC-D`:

- E=1, M=1, X=1 and I=1; D is cleared;
- D, DBR and PBR become zero;
- XH and YH become zero; SH becomes `01`;
- PC is loaded from `00FFFC-D`;
- A, XL, YL, SL and N/V/Z/C are not claimed to have defined hardware reset values.

For deterministic state, fields the hardware reference labels uninitialized retain
their initialized low bits/current flags. This is an emulator storage policy, not a
claim about physical power-on contents. WAI/STP clearing, bus cycles, signal-level
sequencing and RESET timing are not implemented, so the broad RESET task remains in
progress.

## Timing contract

`instruction_cycles` counts W65C816S base processor cycles for successfully completed
instructions. Immediate, absolute and absolute-long 16-bit data adds the documented
width cycle. Absolute indexed reads add one cycle when indexing crosses a page or X
is 16-bit; indexed stores always take that indexed cycle. These conditions share one
cycle rather than stacking. Direct forms use three base cycles and Direct-indexed
forms use four; one cycle is added when DL is nonzero, and a 16-bit data transfer
adds its documented width cycle. The implemented Direct-indirect base cycles are
five or six as listed by the WDC opcode table. They add the same DL and M-width
cycles. `(direct),Y` LDA adds one shared indexed-read cycle when Y crosses a page or
X selects 16-bit index width, while its store has the fixed six-cycle base. The DL,
data-width and applicable indexed-read additions stack. Conditional relative branches
take two cycles when not taken and three when taken. A taken relative branch adds one
more cycle when it crosses a page in emulation mode only; BRA is always taken and
follows the same rule. BRL always takes four cycles and has no page penalty. TAX,
TAY, TCD, TCS, TDC, TSC, TSX, TXA, TXS, TYA, TXY and TYX each take two cycles at
either width. CLC, CLD, CLI, CLV, SEC, SED and SEI also take two cycles. XBA takes
three cycles. Accumulator INC/DEC and INX/DEX/INY/DEY take two cycles at either
selected width. RESET and an unimplemented opcode add no cycles in this subset. The
counter is not SNES master time and excludes 5A22 memory-speed selection,
wait states, bus arbitration, DMA and scheduler time. Those belong to the later
central timing model.

## Sources and limits

The foundation was independently implemented from the Western Design Center
[W65C816S Datasheet, revision March 13, 2024](https://www.westerndesigncenter.com/wdc/documentation/w65c816s.pdf),
particularly sections 2.4-2.11, 2.25, 3.4, 3.5.1, 3.5.3-3.5.8, 3.5.10,
3.5.11, 3.5.12, 3.5.13-3.5.16 and 3.5.20-3.5.21, tables 3-1 and 5-2 through 5-7,
Table 5-5 status effects, Table 5-7 entries 8, 19a/19b, 20 and 21, notes 1, 4,
5 and 6, and caveats 7.2, 7.3, 7.5, 7.8, 7.10, 7.20 and 7.23. Section 3.5 explicitly
establishes a continuous 24-bit data address space whose non-Direct words may span
bank boundaries; the Direct sections and caveat 7.2 establish bank zero and the
E/DL wrap exception. The source establishes register, reset, opcode, address, width,
mode and base-cycle behavior used here. SNES Ricoh 5A22 bus timing still requires
SNES-specific evidence and scheduler integration. No existing emulator implementation
was copied. No external test ROM is committed.

## Verification

`tests/test_cpu_bus.c` covers initialization-before-reset failure, sourced reset
invariants, vector order, logical 24-bit fetch/data addresses, PC bank wrapping,
linear data-word bank crossing, full-address indexed carry, all 82 implemented
opcodes, 8/16-bit loads/stores, N/Z/C changes, REP/SEP/XCE invariants, Direct Page
bank selection/wrapping/DL penalties, regular versus long indirect pointer wrapping,
DBR versus pointer-bank selection, indirect pre/post-indexing and cycle additions,
indexed timing, every conditional branch taken and not taken, signed relative offsets,
BRA/BRL PBR-local PC wrap and native/emulation page-cross timing, isolated D/I/V
status controls in both CPU modes, accumulator/index increment-decrement wrap and
N/Z behavior at M/X-selected widths, every register transfer in emulation/native/
mixed M/X widths, fixed-width C/D/S behavior, XBA byte/flag rules, base cycles and
sticky unknown-opcode stop. Host tests do not establish
complete CPU correctness or console runtime behavior.

## Remaining work

All unlisted opcodes and addressing modes remain unimplemented. Direct Page and
Direct-indirect support is limited to the listed LDA/STA and direct LDX/LDY/STX/STY
forms; indirect JMP forms, Direct read-modify-write, Direct ALU/compare/bit operations,
stack-relative and their remaining edge cases are untouched. The register-transfer
and branch instruction families, single-flag implied status controls and accumulator/
index register increment-decrement operations are implemented; memory INC/DEC,
stack memory instructions and all unrelated instruction families remain separate
unfinished work. Interrupts, decimal arithmetic, stack instructions,
hardware reset sequencing, bus-cycle detail and full timing also
remain unimplemented. Continue with small sourced groups and regression tests.
Implement a complete reference interpreter before considering a dynarec.
