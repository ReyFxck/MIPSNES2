# Core and backend code review — 2026-10-24

## Scope

This review examined the current `main` tree after the CPU-triggered general DMA
integration. It covered the platform-neutral CPU, SNES bus, DMA cursor and timing
bridge, H/V scheduler, PPU reference paths, cartridge composition and the PS2/PSP
build boundary. The review did not import or compare source code from another
emulator and introduced no title-specific behavior.

## Findings

No reproducible correctness, memory-safety or undefined-behavior defect was found
in the reviewed implementation. This is a bounded result, not a claim that the
emulator is complete or hardware-accurate.

The review added `test-cpu-differential`, a deterministic independent driver for
the two CPU execution interfaces already present in the core. For every opcode it
runs four valid initial-state variants through both the aggregate instruction API
and the caller-owned resumable cursor, then compares:

- architectural CPU state and stop/result state;
- aggregate processor-cycle count;
- exact ordered read/write address and value trace;
- effects observed by the synthetic memory bus.

The 1,024 cases pass. This catches accidental semantic or access-order drift
between the two entry points. Both paths share some CPU helpers, so agreement is
not independent proof of W65C816 hardware behavior.

Leak detection was disabled because LeakSanitizer cannot inspect the managed
runtime's process tasks. Clang and the console SDKs were not available locally.
PS2, PSP and host cross-checks for the published revision are delegated to the
pinned GitHub workflows. No emulator or physical-console runtime execution was
performed in this review.

## Reviewed boundaries and remaining risk

- The shared core contains no target SDK include or backend-specific opcode, DMA
  or PPU path; `tools/check_repository.py` enforces this boundary.
- The new test uses deterministic generated bytes and no external emulator data.
- General DMA byte effects still commit at the documented slot-end approximation.
- WRAM refresh, HDMA arbitration, exact dummy/internal cycles, electrical phases,
  APU emulation and complete PPU modes remain unfinished.
- The reference renderer and current synthetic tests cannot establish game
  compatibility or real PS2/PSP performance.

## Completion criterion

This review block is complete when the default, optimized, analyzer and sanitizer
checks pass locally; the 1,024-case differential regression is part of `make test`;
repository policy checks pass; and the published revision passes host, PS2 and PSP
CI. The next implementation milestone remains shared WRAM refresh stalls for CPU
and general DMA.
